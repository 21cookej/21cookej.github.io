Hero Forge.

Upload a real heropack, pull its powers, attributes, and keybinds into a new hero, reuse or repaint its textures, and export a matching renderer — or skip the upload entirely and start from a power preset. Textures and renderers are now resolved from the pack's actual loadTextures(...) / setItemIcons(...) calls, not guessed from folder names.

Or start from a preset (no pack needed)

These fill in tier, attributes, powers, and keybinds using real values pulled from published packs. You'll still need an uploaded pack for pieces/renderer/textures, but you can start building powers and attributes right now.

Build your hero

Basing off a hero copies its tier, pieces, powers (with their internal values, still editable below), attributes, keybinds, and its own textures/renderer over to your new hero. On export, your hero's file is that hero's real file with just those fields patched in place — any imports, custom functions, tick handlers, damage profiles etc. are carried over untouched. Starting from scratch builds a plain, minimal hero file.

Chestplate is required for every hero and always gets written. Leave Leggings, Boots, or Helmet blank if this hero doesn't use that slot — a blank slot is skipped entirely in the export, same as any hero in this pack that only uses one or two pieces.

Attributes the actual numbers

This is where a hero's real power lives — hero.addAttribute(name, value, tier) calls. Powers only turn an ability on; these values are what make Metro Man's punch hit harder than yours. Basing off a hero copies its real attribute values in; presets fill in reasonable starting values you should tune.

Powers

Check every power your hero should have. Open "Edit internal powers & values" on any checked power to turn its internal modifiers on/off or change their values — this isn't limited to the pack's stock configuration. PRESET powers work even without a pack loaded.

Keybinds

Key names are pulled from real addKeyBind() calls and power-internal keys already in this pack. You can still type a custom one.

Sounds carried automatically

Sound events live inside each power's own definition, so picking a power already brings its sounds along — nothing extra to wire up.

Renderer & visuals

Pick an existing hero's renderer as your starting point — this controls the logic (flight physics, beams, cape physics, animations), not which textures get used. Once picked, every texture slot it declares (layer1, layer2, cape, and anything else, including slots it only inherits via extend(...)) is listed below with its own picker, defaulting to that renderer's original texture — but you can point any slot at any texture anywhere in the pack. Pick MetroMan's renderer for the flight logic, then set the cape slot to Black Adam's cape and layer1/layer2 to whatever you want — they're independent choices. Leave the renderer on "none" to hand-write one yourself.

Suit / cape texture slots

One row per slot the renderer actually reads from loadTextures({...}). Each dropdown lists every suit/cape texture in the whole pack, grouped by folder — pick any of them regardless of which hero it originally belonged to, or switch to "Upload / paint custom" for something new.

Ability / item icons

If this renderer has a real renderer.setItemIcons(...) call, positions come straight from it (including %s placeholders, which the game substitutes with the hero's own name at runtime — that substitution was being silently dropped before, which is why icons weren't showing up). Most heroes in these packs don't call setItemIcons at all — they rely on the base renderer's default convention instead: <hero>_0.png for the helmet, _1.png for the chestplate, _2.png for leggings, _3.png for boots, skipping whichever slot has no piece (e.g. Metro Man has no helmet, so only _1/_2/_3 exist for him). Hero Forge now detects which case applies and, for the convention case, follows your current helmet/leggings/boots fields above — so a slot only appears here if this hero actually has that piece.

Beam / laser / effect colors

Every 0xRRGGBB color literal found in the chosen renderer, in order of appearance. These usually drive beams, overlays, and trails. Edit any of them — the export rewrites that exact literal in place. Anything beyond color (unique particle emitters, custom beam geometry) still needs hand-scripting.

Textures & preview

Slot and icon assignment now happens in step 2, right where you pick the renderer, since that's where "which texture goes in which slot" actually matters. This tab is for browsing what's in the pack and previewing the result.

Browse pack textures

Read-only reference — click "Paint a copy" to open the paint tool on any texture; save it, then pick "Upload / paint custom" on the relevant slot back in step 2 to use your painted version.

Preview on player model

This renders your hero's currently selected layer1 / layer2 / cape textures on an actual Minecraft-style player model (not a plain cube), so you can check the UV placement looks right before exporting. Cape is rendered as a flat plane, as intended.

Pick a renderer template in step 2 to enable this preview.

Export

This packages the entire imported heropack, plus your new hero's file, its renderer (if a template was chosen), any customized power files, and its textures — all namespaced to this hero so it never collides with another custom hero you build later.

Particle emitters, unique 3D models, custom beam geometry, and any hand-scripted logic beyond a flat texture swap or color literal still need a human touch — Hero Forge copies and remaps the closest renderer for you, but bespoke effects are still yours to script.
